# Reusable Templates

Templates will standardize the evidence produced across projects and maturity levels. They are not
forms to complete mechanically; each template should explain the decision it supports, who owns it,
and what strong evidence looks like.

## Planned template set

| Template | Purpose |
| --- | --- |
| `AI_Project_Charter.md` | Define outcome, scope, owners, users, constraints, and non-goals |
| `AI_Use_Case_Assessment.md` | Test suitability, value, data readiness, and alternatives |
| `AI_Risk_Assessment.md` | Classify consequence and map risks to enforceable controls |
| `AI_Test_Case.md` | Record input, expected behavior, evidence, risk, and result |
| `AI_Evaluation_Report.md` | Compare baseline and candidate against release thresholds |
| `Prompt_Template.md` | Version a user/task prompt and its evaluation contract |
| `System_Prompt_Template.md` | Define stable behavior, boundaries, and escalation rules |
| `Agent_Design_Template.md` | Define tools, state, guardrails, termination, and ownership |
| `Production_Checklist.md` | Review quality, reliability, security, operations, and business readiness |
| `Incident_Report.md` | Capture impact, timeline, causes, controls, recovery, and follow-up |

## Template quality standard

Implemented templates must include concise guidance, required and conditional fields, completion
criteria, and a worked synthetic example when ambiguity would otherwise remain. They must not request
credentials or unnecessary personal data.

Template changes require review when they alter approval authority, audit evidence, risk categories,
or production ownership responsibilities.

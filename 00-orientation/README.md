# Orientation

Orientation converts a broad intention—“learn AI engineering”—into an explicit capability plan.
It is not a motivational preface. It is where a learner establishes constraints, tests existing
skills, and defines the evidence that will make later progress credible.

## Scope

- Role and capability mapping across software, data, modeling, evaluation, and operations.
- A diagnostic baseline using explanation, debugging, implementation, and design tasks.
- Working-environment requirements for reproducibility, secrets handling, and compute access.
- Learning cadence, evidence collection, review intervals, and gap-based routing.
- Responsible-use expectations for data, models, licenses, and high-impact applications.

## Expected outcomes

By the end of this domain, a learner can describe the type of AI systems they intend to build,
identify concrete gaps against that goal, and maintain a realistic learning plan. They can create a
clean development environment, execute a minimal program, use Git for a reviewable change, and
explain how they will protect credentials and sensitive data.

## Completion evidence

- A dated baseline assessment with observed strengths, gaps, and supporting examples.
- A capability matrix tied to the phases in the root [roadmap](../ROADMAP.md).
- A reproducible environment check that records versions without exposing secrets.
- A study agreement defining weekly capacity, review cadence, and criteria for changing course.
- A first decision note explaining one constraint, choice, and consequence.

## Boundaries

Orientation does not certify competence in later domains, and a self-rating alone is not evidence.
Learners with prior experience should use challenge tasks to test out of material, while retaining
the resulting artifacts as proof.
